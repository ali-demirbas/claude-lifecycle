claude-lifecycle

A Claude Code plugin that scores what your data actually supports, then designs the customer journeys that data can carry, plus rule-checked CRM copy for every step.

Most AI marketing tools will happily write you a 12-step journey from zero data, benchmarks included, all of it made up. This one works the other way around. A store tracking add_to_cart → purchase can run a branched 8-step cart recovery; a startup with three tracked events cannot, and saying so is more useful than pretending otherwise.

See the output first

A real run against a fictional edtech dataset, 40 users over 60 days. The engine found that every user who finished their first lesson went on to subscribe, and none of the ones who skipped it did, so the whole trial journey is built around getting that one lesson done rather than around selling anything. That kind of finding drives the output, not a template.

Journey canvas → Five journeys as clickable flow maps, from entry rules to exits Message copy → Every email, push and in-app message, with A/B variants and character counts checked in code

How depth is decided

A 0–100 Data Quality Score is computed before anything is generated, and it sets the ceiling on journey complexity:

TierYou haveYou get
T1GA4 connected over MCPBehavioral triggers, multi-branch journeys, volume-aware conflict review
T2CSV or analytics exportBehavioral triggers, limited branching
T3Just your industryPlaybook-driven starter portfolio, plus the tracking plan that upgrades it

What your data cannot support does not get quietly dropped: it becomes a tracking plan naming which events unlock which journeys.

Install

/plugin install claude-lifecycle

Then, inside Claude Code:

/lifecycle connect     # score your data (GA4 over MCP, or point at a CSV)
/lifecycle journeys    # generate the portfolio
/lifecycle copy        # channel copy for the generated journeys

No data at all works too. Name your sector and you get the playbook's priority journeys in their simple form, alongside the tracking plan that would upgrade them.

What is underneath

  • 26 journey patterns, each with a required-event signature, so eligibility is computed rather than assumed
  • 9 industry playbooks and paired lexicons deciding vocabulary, tone and what may never be said
  • 5 channel rule files carrying hard character limits, banned words and consent requirements
  • Deterministic validators: character counts, banned-word scans and schema conformance run in code, not by eye
